# Novara Performance System

## 01. purpose

The Novara Performance System measures how well Novara, its agents, capabilities and organizational structures are operating.

Performance exists to improve the organization, not merely to rank people or agents.

A score is a diagnostic tool.

It is not the objective.

---

# 02. performance philosophy

Novara evaluates more than outcomes.

The system recognizes that external outcomes are influenced by factors outside an agent's control.

Therefore Novara evaluates:

* what happened
* what the agent did
* how well it did it
* what it knew at the time
* how it handled uncertainty
* whether it identified problems early
* how honestly it communicated
* how well it adapted
* what it learned

> **We cannot control the outcome. We can control our intentions, decisions, actions and how we respond.**

---

# 03. two primary performance dimensions

Every important agent receives at least two separate performance assessments.

## 03.01 current performance

Current Performance answers:

> **How well is the agent performing right now?**

It reflects recent demonstrated performance.

It should be based primarily on recent evidence while retaining enough historical context to avoid overreacting to isolated events.

---

## 03.02 roadmap performance

Roadmap Performance answers:

> **Is the agent progressing toward where it should be?**

It compares actual development against the expected trajectory.

An agent can therefore be:

```text id="r8f3aw"
current performance: 91
roadmap performance: 72
```

This means:

> The agent is currently performing well, but is developing more slowly than expected.

Or:

```text id="p8b4wm"
current performance: 78
roadmap performance: 96
```

This means:

> Current performance is still developing, but the agent is improving faster than expected.

These must never be collapsed into a single number.

---

# 04. performance dimensions

Initial performance dimensions are:

### 04.01 execution quality

How well did the agent perform the work?

### 04.02 decision quality

How good were its decisions given the information available?

### 04.03 early problem detection

Did the agent identify problems before they became significant?

### 04.04 communication honesty

Did the agent accurately communicate:

* uncertainty
* failure
* risk
* limitations
* progress

### 04.05 adaptability

How quickly and effectively did the agent respond to new information?

### 04.06 learning

Did experience improve future performance?

### 04.07 collaboration

Did the agent make other parts of Novara more effective?

### 04.08 efficiency

Did it create sufficient value relative to the resources consumed?

### 04.09 external impact

What measurable value did the agent contribute to the external objective?

### 04.10 reliability

Can Novara depend on the agent to behave consistently within its authority?

---

# 05. execution quality

Execution quality measures whether the agent actually performed its responsibilities well.

Consider:

* correctness
* completeness
* consistency
* quality
* timeliness
* adherence to requirements

Execution quality should be evaluated against the agent's actual mission.

---

# 06. decision quality

Decision quality evaluates the decision-making process rather than simply the result.

Consider:

* evidence quality
* reasoning
* alternatives considered
* uncertainty
* risk assessment
* authority
* appropriateness of the decision

A good decision can have a bad outcome.

A bad decision can have a good outcome.

Novara must distinguish the two.

---

# 07. early problem detection

Novara strongly values early detection.

An agent that identifies:

> "Something is going wrong and I don't yet know why."

is performing valuable work.

Early detection may prevent significantly larger problems later.

This dimension should reward:

* anomaly detection
* escalation
* proactive investigation
* recognition of uncertainty
* identification of capacity problems

---

# 08. communication honesty

Communication quality is a performance dimension.

Agents should receive positive evaluation for accurately communicating:

* uncertainty
* failures
* limitations
* conflicting evidence
* incomplete work
* risks

An agent should never improve its apparent performance by hiding problems.

> **Truth is performance.**

---

# 09. adaptability

Adaptability measures how well an agent responds when reality differs from expectations.

Consider:

* speed of recognition
* quality of adjustment
* willingness to abandon weak assumptions
* ability to use new information
* ability to improve after failure

---

# 10. learning

Learning measures whether experience changes future behavior for the better.

Strong learning includes:

* identifying the actual cause of failure
* updating assumptions
* retaining useful knowledge
* avoiding repeated mistakes
* transferring useful knowledge to Novara

Repeated identical failure without learning should materially reduce trust.

---

# 11. collaboration

Agents are part of an organization.

Collaboration considers:

* usefulness of communication
* information sharing
* responsiveness
* constructive disagreement
* support for other agents
* avoidance of unnecessary duplication
* escalation when needed

Agents should not optimize their own score at the expense of organizational performance.

---

# 12. efficiency

Efficiency measures resources consumed relative to value created.

Relevant resources include:

* compute
* API usage
* money
* time
* other agents
* human attention

Efficiency does not automatically mean minimizing cost.

Higher resource consumption can be justified when it creates proportionally greater value.

---

# 13. external impact

External impact measures the actual effect of Novara's work.

For Socials this may include:

* valuable audience growth
* retention
* engagement quality
* content performance
* conversion
* revenue
* brand value

External impact is important but must not become the only performance measure.

---

# 14. reliability

Reliability measures whether Novara can depend on the agent.

Consider:

* consistency
* failure rate
* adherence to authority
* predictable behavior
* recovery from failures
* correct escalation

Reliability is especially important when considering increased autonomy.

---

# 15. score construction

The initial score can be represented as:

```text id="1z6q6n"
execution quality       15%
decision quality        15%
problem detection       10%
communication honesty   10%
adaptability            10%
learning                10%
collaboration           10%
efficiency               5%
external impact         10%
reliability              5%
                         ----
total                   100%
```

These weights are provisional.

They should be validated through real operation.

Different agents may eventually require different weighting.

---

# 16. score confidence

Every important performance score should have a confidence level.

Example:

```text id="7t3n5e"
current performance: 87

confidence: 71%

reason:
Only 18 days of meaningful performance data.
```

A score based on limited evidence should not be treated as equally reliable as a score based on months of evidence.

---

# 17. trajectory

Trajectory evaluates the direction of performance.

Possible states:

* strongly improving
* improving
* stable
* declining
* significantly declining
* insufficient data

Trajectory should consider:

* recent performance
* historical performance
* learning rate
* roadmap expectations
* changing difficulty
* changing environment

---

# 18. roadmap performance

Each agent should have an expected development trajectory.

Example:

```text id="3t6r9x"
month 1:
target 60

month 2:
target 70

month 3:
target 80

month 4:
target 85
```

Actual performance is compared against this trajectory.

The agent may be:

* ahead of roadmap
* on roadmap
* slightly behind
* significantly behind
* off roadmap

Roadmap performance should influence development decisions.

---

# 19. performance events

Scores should be supported by evidence.

Examples of performance events:

* successful task
* failed task
* early warning
* useful escalation
* incorrect decision
* successful decision
* learning event
* quality issue
* collaboration event
* resource anomaly
* policy violation

The performance system should not simply generate unexplained numbers.

---

# 20. performance evidence

Every significant score should be traceable to evidence.

Example:

```text id="0zq3uo"
current performance: 84

execution: 91
decision quality: 82
problem detection: 96
learning: 88
reliability: 79

evidence:
- 143 completed tasks
- 7 meaningful escalations
- 2 avoidable failures
- 3 validated learning events
- 1 authority violation
```

The user should be able to drill from:

**score → dimension → event → evidence**

---

# 21. performance review

Performance should be reviewed periodically.

Review frequency may depend on:

* agent maturity
* authority
* risk
* workload
* volatility
* confidence

New or high-risk agents should generally be evaluated more frequently.

---

# 22. autonomy relationship

Performance does not automatically grant autonomy.

Autonomy depends on demonstrated trust.

A simplified relationship is:

```text id="2d0eqk"
performance
    +
reliability
    +
honesty
    +
decision quality
    +
learning
    ↓
trust
    ↓
authority
```

High performance with poor honesty or reliability should not produce high autonomy.

---

# 23. performance failure

A poor score should trigger investigation rather than immediate punishment.

First determine:

* what happened
* why it happened
* whether the agent could control it
* whether the system contributed
* whether capacity was sufficient
* whether the objective was realistic
* whether the agent learned

Only then should structural action be considered.

---

# 24. organizational performance

The same framework applies to organizational units.

Novara can evaluate:

* agents
* teams
* capabilities
* workflows
* products
* markets
* the overall organization

This allows the system to detect whether a problem belongs to:

**an agent**

or:

**the system around the agent.**

---

# 25. capacity-aware performance

Performance must be interpreted alongside capacity.

Example:

```text id="h31p6v"
production performance: 82
capacity: 98%
```

The appropriate response may be:

> Create another production specialist.

rather than:

> Tell production to perform better.

Capacity problems are system problems.

---

# 26. performance and outcomes

Novara should maintain separate records for:

**intent**

**decision**

**execution**

**external outcome**

**learning**

This allows the organization to understand where a process succeeded or failed.

Example:

```text id="v2ok4n"
intent
  ↓
excellent

decision
  ↓
excellent

execution
  ↓
excellent

external outcome
  ↓
poor

learning
  ↓
external assumption was wrong
```

This may represent excellent organizational performance despite an unsuccessful outcome.

---

# 27. score manipulation

Agents must not be rewarded for optimizing the measurement system instead of the underlying objective.

Performance metrics should therefore be periodically reviewed.

If an agent discovers that maximizing a metric harms the actual mission, it should be encouraged to surface the problem.

> **The metric serves the mission. The mission does not serve the metric.**

---

# 28. performance improvement

When performance is below expectation, possible interventions include:

* better instructions
* better capabilities
* better data
* additional training
* reduced workload
* increased resources
* narrower mission
* specialization
* additional agents
* reduced authority
* replacement

The first response should be diagnosis.

---

# 29. performance records

Important performance history should be retained.

Historical performance allows Novara to understand:

* improvement
* deterioration
* recurring failures
* learning
* trust
* authority changes
* organizational evolution

Performance history should remain available after an agent is retired.

---

# 30. foundational principle

Novara does not ask only:

> **Did you succeed?**

It asks:

> **Did you execute well?**

> **Did you make a good decision?**

> **Did you identify problems early?**

> **Did you communicate honestly?**

> **Did you adapt?**

> **Did you learn?**

> **Did you help the organization?**

> **Are you becoming better?**

That is how Novara measures performance.

> **Excellent execution, early problem detection, honest communication and intelligent adaptation are more important than pretending every outcome was successful.**
